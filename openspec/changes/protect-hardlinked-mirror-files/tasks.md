## 1. Implementation

- [ ] 1.1 In `FileSystemContentStore.PlaceAtMirrorPath`, after `Kernel32.CreateHardLink(stagingPath, blobPath)` succeeds (both the direct hardlink branch and the branch where a hardlink attempt succeeds after a previously forced/per-blob failure), set `File.SetAttributes(stagingPath, File.GetAttributes(stagingPath) | FileAttributes.ReadOnly)` on the staged file before the final `File.Move`.
- [ ] 1.2 In the copy-fallback branch (`CopyWithProgress` call, both the no-hardlink-support case and the hardlink-attempt-failed case), explicitly ensure the staged file is not read-only (e.g. clear `FileAttributes.ReadOnly` if present on the newly-created staged file) so a stale attribute can never leak through, even though a fresh `FileMode.CreateNew` file should not carry it by default.
- [ ] 1.3 Verify `File.Move(stagingPath, mirrorPath, overwrite: true)` carries the staged file's `FileAttributes.ReadOnly` state through to `mirrorPath`, replacing whatever attribute the previous mirror entry at that path had (confirms the design's "no separate stale-attribute-clearing step needed" decision) - covered by the placement-kind-transition tests in section 2.

- [ ] 2.2 Add a test asserting that a file placed via `PlaceAtMirrorPath` on a store without hardlink support (or via the forced-hardlink-failure copy fallback) results in a mirror file without `FileAttributes.ReadOnly`, and that its content can be overwritten in place without error.
